# ADR-006 migration history append-only

## 背景

Drizzle 0.xで作成したマイグレーションは`main`へ取り込まれていますが、Drizzle v1用の
マイグレーションはまだ`main`へ取り込まれていません。本番データベースは未作成であり、既存の
ローカル開発データベースは破棄して作り直します。

この状態で旧履歴からの更新経路を製品契約にすると、利用対象のないマイグレーション台帳更新、既存
データ補完、履歴変換、二重のテスト経路を永続的に保守することになります。現在のスキーマを新規
データベースへ一度で適用できる単一の基準マイグレーションを採用し、永続データベースが存在してから
追記専用の運用を開始します。

## 決定

### 今回に限りマイグレーション履歴を作り直す

今回のDrizzle v1更新では、既存マイグレーションを変更しない通常規約の明示的な例外として、
`packages/db/drizzle/**`と、変更ブランチ上で生成済みの複数の`packages/db/drizzle-v3/**`を削除します。
リポジトリに残すマイグレーション履歴は、現在のスキーマを表す単一の基準マイグレーションだけです。

この例外は、本番データベースが未作成で、ローカル開発データベースをリセットする今回だけに限定します。
将来の既存マイグレーションを変更する一般的な許可にはしません。

### 新規データベースは単一の基準マイグレーションから始める

Drizzle v1の実行対象は
`packages/db/drizzle-v3/20260823163505_baseline/{migration.sql,snapshot.json}`です。この基準
マイグレーションは、現在のテーブル、列、インデックス、外部キー、検査制約に加え、スキーマだけでは
生成できないリポジトリ所有のトリガー、SQLiteで明示的にNULLを拒否するテキスト主キー、現在有効な
Lunaの料金行を含めます。

過去のマイグレーションを適用済みのデータベース、過去のマイグレーション台帳、既存行を受け入れる
更新経路は持ちません。履歴変換、マイグレーション台帳の移行、既存データ補完、マイグレーション
接頭辞、二重実行、独自のマイグレーション読み込み処理も追加しません。

### 基準マイグレーションの取り込み後から追記専用にする

基準マイグレーションは、Drizzle v1更新を含む変更が`main`へ取り込まれるまでは同じ変更内でレビューし、
現在のスキーマへ一致させます。`main`へ取り込まれた時点からSQLとスナップショットを一体として不変にし、
以後のスキーマ変更とデータ移行は
`packages/db/drizzle-v3/<YYYYMMDDHHmmss>_<tag>/{migration.sql,snapshot.json}`を完全な新規
ディレクトリとして追加します。

## 理由

保持すべき永続データがないため、新規データベースだけを対象にすることが最小で検証可能な契約です。
Drizzle v1の標準マイグレーターへ単一の履歴を渡し、利用対象のない移行処理とテストを持たないことで、
実行経路、マイグレーション台帳、保守対象を一つにします。

## 検討した代替案

- 過去の更新経路を維持する: 利用する永続データベースがなく、変換、照合、移行テストだけが保守対象に
  なる
- マイグレーション台帳をDrizzle v1へ移行する: 存在しない永続データベースのための移行経路になる
- `drizzle-kit push`で現在のスキーマへ合わせる: 保存済みSQLをレビューして再現する契約を失う

## 結果

ローカル開発データベースは、開発サーバーを停止してリセットし、必要な場合だけ開発用初期データを
投入します。既存のローカルデータは引き継ぎません。

本番データベースはまだ作成されていません。初回作成時は空のデータベースへ基準マイグレーションを
適用し、通常の認証とorganization作成フローから利用を開始します。本番への導入と遠隔データベースの
変更は、この判断だけでは許可しません。

基準マイグレーションが`main`へ取り込まれた後に問題が見つかった場合は、基準を編集せず新しいv3
マイグレーションで前方修正します。永続データベースの運用開始後は、バックアップと復元手順を伴う
通常の追記専用運用へ移行します。

## 強制方法

- `packages/db/drizzle/**`が存在しないことを検査する
- Drizzle v1更新を含む変更では、`packages/db/drizzle-v3/**`が単一の基準マイグレーションだけである
  ことを検査する
- 基準マイグレーションが`main`へ取り込まれた後は、既存の`packages/db/drizzle-v3/**`の変更、削除、
  改名を拒否し、完全な新規ディレクトリの追加だけを許可する

## 検証

- 空のデータベースへ基準マイグレーションを適用し、現在のスキーマと外部キー検査へ到達する
- マイグレーション台帳に基準マイグレーションの1行だけが記録される
- リポジトリ所有のトリガーと現在有効なLunaの料金行が作成される
- 現在のスキーマとv3履歴の不整合、および削除した履歴への参照がないことを静的に検査する
- リセット後の空のローカル開発データベースと、任意の開発用初期データ投入を検査する
